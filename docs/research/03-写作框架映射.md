# 写作框架如何进入 Composer

作者的框架将 domain、process、resources、governance 分开，并定义中文生成前约束、单对象变更、整章回读、日志和角色协作。[框架入口](https://github.com/icimik/fiction-writing-framework/blob/master/SKILL.md)

阶段文档是执行入口，包含从立项到结项、整书精修、发布裁决和停止正文大修的规则；项目结构区分正式章、样章、原始资料、裁决结论、质量和发布资产。[阶段流程](https://github.com/icimik/fiction-writing-framework/blob/master/references/02-process/stages.md) [目录结构](https://github.com/icimik/fiction-writing-framework/blob/master/references/02-process/project-structure.md)

## 映射与实现状态

| 框架能力 | 首版状态 | 实现位置／下一步 |
|---|---|---|
| 中文生成约束 | 已接入完整上游文件到 system prompt | `framework/中文生成约束.md`、`electron/ai.cjs` |
| 当前章、人物、世界、大纲、风格 | 已提供文档类型与勾选 AI 参考 | `src/App.tsx`、`electron/store.cjs` |
| 单次聚焦一个章节 | AI 请求只操作一个章对象 | 非章文档不允许正文生成任务 |
| 表达精修不改结构 | 作为模型指令与作者裁决要求 | 无自动结构一致性证明 |
| 正文改写整章 | 优化返回完整章，不做局部搜索替换 | 模型可能不遵守，需作者检查 |
| 采纳前审阅 | 提案预览、采纳／放弃 | 首版无逐行 diff |
| 变更追溯 | JSONL 变更日志、整篇快照、提案状态 | 正文事务级原子写入；跨文件非数据库事务 |
| 阶段与质量 | 简化阶段＋作者手工检查 | 不等价于完整 0–10 与 7b 流程 |
| Writer／Reviewer／Reader／Editor | 尚未自动编排 | 下一版本，结构化评审、Reader 画像和 Editor 裁决 |
| 样章转正／归档 | 尚未实现 | 正式目录和样章生命周期需单独加入 |
| SOUL／STYLEGUIDE 模板 | 现为可编辑人物／风格文档 | 模板生成、引用规范及角色上下文自动装载后续实现 |
| 框架版本管理 | 当前固定快照版本 | 后续每作品绑定版本与显式升级 |
| 发布准备 | Markdown 导出 | 不等价于 Pandoc／EPUB／校样流程 |

## 关键取舍

- **作者手动编辑**：可逐句编辑；框架对 AI 正文改写的整章要求不应禁止正常键盘操作。
- **续写**：只新增内容，采纳时附在当前章后；已存在正文的“生成”被阻止，避免混淆新生成与改写。
- **评价边界**：机械检查和模型意见不能代替文学判断，不显示虚假的“质量 4.8 分”“已通过整书审阅”。
- **文档类别**：首版以轻量资料类型贴合框架，不直接在 UI 中暴露全部数字目录。目录结构保留可迁移性。
- **上游原文**：快照未经删改；其成因解释属于上游观点，不作为本项目已科学验证的 LLM 内部机制结论。

## 待补规格

下一轮需将 framework defaults 与阶段流程的不同粒度统一为显式参数；定义样章状态、审批与回退；明确表达精修、中文重塑的授权门禁；细化质量清单和发布资产联动。IF 的对象粒度和验收标准只在其模块启动时扩展，不自动改写上游框架。
