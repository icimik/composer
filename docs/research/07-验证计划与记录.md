# QA 清单与验收边界

本文件定义功能与视觉验收范围，原开发轮结果在 `verification-results.md`，后续提交的实际 CI 与修复记录在 [current-verification.md](current-verification.md)。不能把有测试源码、配置了 CI 或 mock 服务成功视为完成原生人工验收。

## 自动化覆盖清单

| 要求／控制 | 功能验证 | 可见证据 |
|---|---|---|
| 新建／打开 workspace | 新建隔离、原路径打开、重新启动 | select、正文、路径 |
| 新建／切换 session | prompt 与位置独立，正文共享 | tab、指令、提案 |
| 文档类型 | 章节／人物／世界／大纲／风格 | 文档树、标题 |
| 保存 | 自动、快捷、关闭刷新、冲突 | 已保存、待保存、失败 |
| 历史恢复 | 旧稿恢复且再次可恢复 | 快照列表、编辑器 |
| 结构总览 | 点击章卡返回正文 | 标题和字数 |
| 阶段检查 | 阶段／勾选持久化 | 下拉框、checkbox |
| AI 配置 | 密钥不回传、HTTPS 限制、安全存储拒绝 | 设置确认、错误提示 |
| AI 生成／优化／续写 | HTTP adapter、整章／追加语义 | 提案先于正文变化 |
| AI 取消／错误 | 限流、空结果、取消不修改正文 | 可取消按钮、错误 |
| AI 上下文 | 仅明确选定的资料 | mock 接收的请求 |
| 采纳／放弃 | 正文 hash 检查、可逆快照 | 已采纳／放弃提示 |
| 快捷操作 | 命令面板、专注、保存 | dialog、栏位可见性 |
| 主题／字号／面板 | light／dark、标准／较大、收起／展开 | 对应布局 |
| 导出 | 只含章节、真实保存路径 | 实际文件 |
| 安全 | Node 不可见、正文 HTML 不执行、子 frame IPC 拒绝 | runtime preferences、状态不变 |

Playwright Electron 测试会启动真实桌面窗口，通过 UI 操作验证，AI 服务仍为本地 mock。Playwright 官方明确 Electron 支持属于 experimental，并提供 launch 和 firstWindow；因此锁定依赖、记录平台与版本尤为必要。[Playwright Electron API](https://playwright.dev/docs/api/class-electron)

## 视觉与设计验收

- **场景**：初始写作、包含真实中文的正文、结构总览、检查清单、设置对话框、历史、错误、AI 提案。
- **模式**：明暗两种模式；目标桌面 1500×960 与最小 900×640；200% 缩放和窄宽度展示。
- **输入**：Tab 顺序、键盘快捷键、dialog 焦点与 Escape、输入标签、聚焦边框。
- **状态**：默认、悬停、聚焦、禁用、生成、空、失败、成功；每个明显控制都要验证。
- **测量**：前景／背景、选中态、错误态、按钮、边框和 focus 对比度；规范／展示／CSS token 漂移检查与故意篡改的反例。
- **边界**：操作系统强制高对比归 OS 调色板，不注入品牌色；减少动态偏好下无转场；界面无仅靠颜色表达的关键状态。

设计规范和展示页遵循作者 skill 的“双产物、token 一致、真实场景、测量而非目测”要求。[design-system skill](https://github.com/kimmywork/skills/blob/master/drafting/skills/design-system/SKILL.md)

## 探索性失败场景

- **外部改稿**：在打开期间改写磁盘文件，再保存，必须拒绝覆盖并保留当前输入。
- **生成后改稿**：先得到提案，再改正文，旧提案不能采纳。
- **关闭即保存**：输入后不等 debounce 立即关闭，再启动，保留最新输入。
- **跨工作区迟到结果**：生成期间不得切换或创建并切过去；取消后无晚到正文。
- **损坏索引**：不重置成空项目，不静默覆盖损坏文件。
- **符号链接**：正文与内部元数据不可借链接越出工作区。
