# Icimik Composer 后续设计与竞品调研

本轮围绕中文小说、选择式 Interactive Fiction、世界模拟 Text Adventure、Visual Novel／GalGame 及 OpenAI-compatible Chat Completions 辅助创作展开设计。研究采用官方功能页、帮助文档和语言／运行时文档，覆盖 12 个工具；结论是设计建议，不是实机体验、文学质量排名或对全部市场产品的穷尽审计。

研究日期：2026-10-09 UTC／2026-10-08 America/Los_Angeles。应用基线为 PR #1 中的 `1246f30`，框架基线为 `3b6d014f7879d190e398f2dd7798c933eb1a1c9b`；以下计划不表示相应功能已经实现。

本报告保留调研时的历史基线和议题拆分。Windows 阻塞现已修复并通过原生 CI，当前证据、未执行验收及 artifact 策略见[最新验证记录](current-verification.md)；后文的基线失败不应读作当前状态。

## 产品边界与顺序

保留本地优先、macOS／Windows、无需账号、不远程同步、AI 可选及作者最终裁决。小说是首个完整工作流，选择式 IF 是第二个闭环，VN 在共享叙事状态之上添加演出层；世界模拟与中文 parser 单独推进，不能用分支链接冒充世界规则。

- **先稳定小说**：修复实际 Windows 验证阻塞，补数据恢复、框架版本契约、AI 能力适配和提案差异。
- **再完成选择式 IF**：数据模型、图编辑、确定性 runtime、存档与路径测试共同形成可交付闭环。
- **再扩展 VN**：对白／演出脚本、资源治理、预览、读档／回滚、有限 Ren’Py 导出。
- **独立验证 Text Adventure**：世界实体与动作规则先于输入解析；中文 parser 先限定句型，不以在线 LLM 代替可信动作执行器。
- **暂不承诺**：账号、云同步、多人协作、市场、自动公开发布、所有引擎双向无损转换、自动生成完整游戏。

## 小说组织与改稿

### Scrivener：修订单位与正式稿

Scrivener 的文档快照支持命名、Compare 和 Roll Back，并提供集中管理；Status／Label 各单值，Keywords 可多值，Outliner 展示元数据。（[官方修订指南](https://scrivener.tenderapp.com/help/kb/general/revising-in-scrivener)）

设计启示：让章节／场景拥有稳定身份，按修订原因保存快照，差异与恢复不等于另建正式稿。Composer 已有整篇历史，下一步是可审阅差异、恢复前保护和修订批次；不把复制草稿文件夹作为默认会话语义。

### novelWriter：文件结构与叙事结构分离

novelWriter 支持文档排序、文件夹、子文档、元数据交叉引用，Novel View 按章／场景标题组织，Outline View 显示关联信息；独立查看面板和 Focus Mode 支持边写边参考。（[官方功能页](https://novelwriter.io/features.html)）

它的 Build Manuscript 能筛选小说、大纲与笔记，并输出 Markdown、HTML、办公文档及 PDF。（[官方功能页](https://novelwriter.io/features.html)）

设计启示：作品树、正文和结构总览应是同一数据的视图，不产生重复稿件。卷／章／场景顺序、跨引用、搜索与导出选择需要共同规格；中文输入法和性能必须另行真实测试，不能由竞品功能页推定。

### Plottr：模板应当是可版本化的结构资产

Plottr 的自定义 Timeline Template 保存 plotlines、scene cards、顺序及人物／地点／标签关联，并明确原 Timeline 后续修改不会自动更新已存模板。（[模板文档](https://docs.plottr.com/article/149-custom-timeline-templates)）

设计启示：导入故事圈、三幕等框架时记录模板版本和来源，以提示引导作者，不强制把故事填满公式。故事时间与章节顺序分离；设定联动和伏笔追踪先做可解释引用，不宣称自动证明文学一致性。

## AI 写作与上下文

### Novelcrafter：显式资料选择与接口灵活性

Novelcrafter 可把 Codex 条目附到场景上下文并在 prompt preview 检查；其文档提醒过多资料、细节埋藏、设定冲突和缺少场景规划会降低效果。（[场景上下文指南](https://www.novelcrafter.com/courses/codex-cookbook/codex-scenes)）

OpenAI Compatible Connection 接收 BaseURL 和 API key，支持自动发现模型及手工模型列表；它还记录了兼容标准实现差异与浏览器连接限制。（[接口文档](https://www.novelcrafter.com/help/docs/ai-connections/openai-sdk-compatible)）

设计启示：Composer 应显示完整发送范围、角色／场景引用、摘要来源和预算；模型发现不是硬依赖，未知模型可手填。Electron 主进程的连接边界不同于浏览器竞品，因此不能照搬竞品的 CORS 限制为 Composer 限制；“compatible”也不等于所有参数都受支持。

### Sudowrite：生成结果先是候选，不是正文

Sudowrite 的 Write 提供 Auto／Guided／Tone Shift，可结合前文及 Story Bible 的风格、人物、世界设定与章节概要，生成候选卡片后由作者 Insert。（[Write 文档](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/write/pvxUvbQqYybfEosqx1sXjY)）

设计启示：借鉴“引导生成＋候选比较”，不照搬字数承诺为中文 token 预算，也不把模型输出视为设定真相。小说、IF 场景和 VN 对白使用不同对象粒度，但都要求基线 hash、作者采纳、原子写入和日志。

### 协议依据：Chat Completions，不扩成另一套 AI 产品

OpenAI 官方文档区分 `max_completion_tokens` 与已弃用的 `max_tokens`，提醒模型参数支持不同；流式结果是 `delta`，最终 usage chunk 可能在断流时缺失，结束原因包含 `length`、`content_filter` 等。（[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)）

设计启示：提供显式能力配置、参数校验和非流式后备，服务未知时不猜精确费用；保留断流草案但禁止默认为完整结果。JSON Schema、工具调用或 streaming 只按已确认能力启用；IF／VN 结构化输出仍需本地 schema 和引用校验。版本范围聚焦 Chat Completions，不强制迁移 Responses API。

## 选择式 IF 与叙事设计

### Twine：作者工具与播放器不是一个东西

Twine 将故事拆为 passages，指定 start passage；story format 决定玩家端呈现、条件和变量，HTML 可独立游玩，Twee 是不可独立运行的文本交换格式；不同 story format 之间迁移可能耗时。（[基本概念](https://twinery.org/reference/en/getting-started/basic-concepts.html)）

设计启示：Composer 自有模型必须分别定义创作数据、运行数据和导出适配；图上可连通不等于条件满足时可到达。Twee 导出必须锁定格式和有限语法范围，不能宣称兼容全部 Harlowe／SugarCube。

### ink／Inky：分支必须能汇流、复用与运行

ink 的 knots／stitches、choices、diverts、gathers 和变量支撑分支及重新汇流；一次性与可重复选择的语义不同。（[Writing with ink](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md)）

Inky 支持边写边试玩；ink 提供编译器与运行时，编译 JSON 可用于引擎集成，Inky 的 web export 使用 inkjs，官方说明其不是完整游戏引擎。（[官方仓库](https://github.com/inkle/ink)）

设计启示：场景图与文本编辑双向定位，子图可折叠，类型化状态驱动选择；试玩提供状态变化、路径记录和可复现错误。暂不承诺 ink 全语言导入；先证明受限子集及不支持项诊断。

### articy:draft：看得见的条件与效果

articy:draft 使用条件和指令区分判断与状态变更，支持 Boolean／Integer／String 全局变量及模拟；文档特别说明模拟不执行所有模板属性脚本。（[官方脚本文档](https://www.articy.com/help/adx/Scripting_in_articy.html)）

设计启示：同一条件 AST 在 UI、静态检查和 runtime 中复用，调试器清楚区分“已验证”“仅结构检查”“未覆盖”。不应把有限模拟范围包装成全路线可达性证明，也不为单作者引入重型团队生产系统。

## 世界模拟 Text Adventure

### Inform：输入解析与动作执行分层

Inform 用 Understand 将命令映射到动作，动作区分 Check／Carry out／Report，并提供 ACTIONS／RULES 调试信息。（[新命令文档](https://ganelson.github.io/inform-website/book/RB_6_2.html)）

设计启示：中文输入和动作菜单调用同一执行器；规则检查失败时不能先改变状态再解释。有限中文句型、别名、同名实体消歧和“看不见／够不到／缺工具”反馈需独立验收，不假设英语自然语言编程机制直接适用中文。

### TADS：世界模型不能只剩变量与链接

Adv3 包含地点、角色、容器、门锁、可携物件、光源及对话模型，并处理输入歧义和隐含动作。（[对象库概览](https://www.tads.org/ov_lib.htm)）

设计启示：先实现“房间、钥匙、门、背包、检查、拿取、开锁”的小模型，再评估对话与隐含动作；不重做完整 Adv3，也不把物理模拟默认成本塞给普通小说作者。菜单可玩必须先成立，parser 是独立输入适配。

## Visual Novel／GalGame

### Ren’Py：演出脚本与存档语义

Ren’Py 使用 label、menu、jump、default、条件、对白及 scene／show／hide／with／音频等语句组织作品，并提醒 lint 不能替代完整测试。（[官方入门](https://www.renpy.org/doc/html/quickstart.html)）

其存档和回滚在语句／交互边界恢复，存在可保存状态的范围限制，且跨版本存档兼容不保证。（[存档与回滚文档](https://www.renpy.org/doc/html/save_load_rollback.html)）

设计启示：为对白块建立稳定 ID，资源引用与演出状态进入可恢复快照；快进、自动播放、回滚和跨版本存档均有明确策略。有限 Ren’Py 导出产生可编辑源码、映射表和兼容报告，不将世界模拟逻辑静默丢失，也不自动运行任意 Python。

### TyranoBuilder：低代码与即时演出

TyranoBuilder 官方强调拖放编辑、浏览器导出及演出功能，移动分发还需要第三方转换软件。（[官方功能页](https://tyranobuilder.com/)）

设计启示：借鉴“对白＋演出块＋即时预览”的工作流，不在首期实现视频背景、相机动画、Live2D 等全部能力。其宣传将 Live2D 描述为 3D animation，本报告不沿用该术语，也不据此推断素材制作能力或导出质量。

## 框架治理与跨媒介差距

上游 `SKILL.md` 要求目标读者缺失或题材无法判定时询问用户，但主执行入口 `stages.md` 给出默认读者与“都市异能”；默认交付、全书目标和样章要求也需要区分，应用不能自行选择一个规则并隐瞒冲突。（[入口规则](https://github.com/icimik/fiction-writing-framework/blob/3b6d014f7879d190e398f2dd7798c933eb1a1c9b/SKILL.md)，[阶段规则](https://github.com/icimik/fiction-writing-framework/blob/3b6d014f7879d190e398f2dd7798c933eb1a1c9b/references/02-process/stages.md)）

主流程含阶段 7b 条件触发与用户授权、样章转正／归档、至少三个 Reader 画像及发布期停止正文大修规则。（[阶段规则](https://github.com/icimik/fiction-writing-framework/blob/3b6d014f7879d190e398f2dd7798c933eb1a1c9b/references/02-process/stages.md)）

设计建议：把上游默认值冲突与 novel／choice-IF／world-IF／VN profile 提案放在框架仓库，应用只做版本化适配。多角色审阅是软件功能设计，不代表本轮已运行多 Agent 或真实读者研究；AI 读者反馈要明确标识为模拟。

## 研究限制与下一步验证

本轮未登录试用竞品，不报告价格、用户数、市场份额、中文文学质量或未确认的离线／隐私能力。页面未提及的功能标为未确认，不写成竞品不支持；抽取页的历史实现细节不作为当前 SDK 版本推荐。

后续设计 issue 的关闭条件是规格和测试样例被评审，而不是仅写一份方案。建议用一部含卷／章／场景的短小说、一部有分支／汇流／循环的 IF、一个钥匙门锁 Text Adventure、一个双路线 VN 作为逐步验证样本；性能阈值先建立基线再由作者确认，不承诺未经测量的发行日期或模型效果。
