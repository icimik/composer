# Electron 架构与安全决策

目标平台按用户要求采用 macOS／Windows，技术栈为 Electron + React + TypeScript + Vite。首版不需要远程服务器、账号库或同步协议，避免把本地产品变成云端依赖。

## 进程与权限

- **Main**：文件读写、元数据校验、原生打开／导出对话框、系统密钥加密、HTTPS AI 请求与取消。
- **Preload**：只暴露命名操作，不暴露 `ipcRenderer`、`fs`、shell、任意文件路径读取或任意命令执行。
- **Renderer**：UI、编辑缓冲、选择上下文与提案展示；无 Node 集成，启用 context isolation 和 sandbox。
- **资源**：使用 `composer://app/` 自定义协议，只服务构建目录内资源，拒绝窗口跳转、新窗口和权限请求。

该边界依据 Electron 对 Node 集成、隔离、sandbox、导航、新窗口、IPC 发送方校验与自定义协议的建议；并非因为 Electron 默认配置就认为应用安全。[官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

IPC 允许唯一应用窗口的主 frame，URL 必须是精确的 `composer://app/`。这里不能用 Node `URL.origin` 判断自定义协议，因为其可能为 `null`；源窗口、主 frame 与固定页面三者共同校验。

## 文件与恢复

正文以 Markdown 为唯一来源，JSON 元数据保存结构及会话。写入先落唯一临时文件、sync 后 rename；同一进程变更串行化，避免并发 read-modify-write 丢更新。

每次读正文计算 SHA-256，保存必须匹配预期 hash。已被外部编辑的文件不会被覆盖；当前输入保留。首版未实时监听文件，用户需要重新打开工作区加载新基线。

保存正文前写入历史，再写正文与元数据，最后日志。单文件替换是原子的，但多文件更新不是完整 ACID 事务：极端崩溃可能导致日志或状态落后，需要后续 transaction journal 和启动时 reconciliation。不能以“atomic write”宣称任意断电无损。

工作区目录、正文与内部元数据路径校验真实路径；拒绝越界目录与符号链接文件。单实例锁防止同一安装的多个进程并行改稿，但不是多应用／多设备锁。

## AI 与凭据

支持 OpenAI 兼容的 `/chat/completions` 请求。服务基础地址需 HTTPS、不含 URL 账号、查询或 fragment，拒绝重定向以防凭据发送到意外地址。请求不从渲染器出网。

密钥经 Electron safeStorage 加密，文件与作品目录分开。macOS 使用 Keychain，Windows 使用 DPAPI；Windows 的保护不等价于抵御同一用户下其他恶意应用，macOS 一致签名有助于 Keychain 识别。[safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)

系统加密不可用时拒绝保存；Linux `basic_text` 也拒绝作为产品安全存储。当前使用同步接口，可能有 OS 提示或阻塞；切换官方异步接口是后续工程改进。[safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)

模型收到当前章、指令、明确勾选的设定与中文生成约束。上下文长度有 150000 字符上限，非 token 精确预算；非流式输出，有 60 秒超时。模型产物必须是有效文本，错误正文不回显服务端原始内容。

当前没有真实供应商密钥，因此验收以真实 HTTP 路径＋本地 mock API 进行，不宣称完成所有真实模型兼容或文学质量验证。流式、原生供应商协议、重试与更精确 token 预算后续增加。

## E2E 特殊边界

测试启动条件为未打包且 `COMPOSER_E2E=1`，用临时目录、进程内 AES-GCM fixture vault 与 127.0.0.1 mock API。产品包不可启用测试模式，生产路径不允许明文 HTTP 或假安全存储。

Linux E2E 的 `--no-sandbox` 是容器测试启动参数，不是产品 BrowserWindow 的 `sandbox:false`。macOS／Windows CI 不传该参数；原生 sandbox 与 OS 密钥仍需分别验收。

## 已知限制与下一步

限制包括 metadata 和历史体积增长、无外部实时监听、无单个损坏 workspace 的隔离启动恢复、无密钥清除 UI、无逐行 diff、无分卷和场景层、未实现正式发行签名／公证。应该在真实稿件投入前补完数据恢复和原生系统测试，不把开发版称为正式发行版。
