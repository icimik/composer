# 竞品研究细节

每节列出实际读取的官方证据、研究问题和 Composer 的产品判断。这里不是功能全量审计，也不把“所读页面未提及”解释为产品不支持。

后续跨媒介调研补充 Plottr、Sudowrite、ink／Inky、articy:draft 与 TyranoBuilder，连同本页已有工具形成 12 项证据集，见 [09 后续设计与竞品调研](09-后续设计与竞品调研.md)。该补充包含设计取舍与已创建 issue 引用；仍是官方文档研究，不是已登录试用或文学质量测评。

## 小说与本地工作流

### Scrivener

**研究问题**：长篇改稿如何避免丢掉旧版本，又不制造不知道哪份才是正式稿的副本？

- **证据**：Snapshots 在文档粒度保留当前内容，支持 Compare 与 Roll Back；可命名快照、批量建立和集中管理。[官方修订指南](https://scrivener.tenderapp.com/help/kb/general/revising-in-scrivener)
- **证据**：Status 和 Label 各只能同时选一个，而 Keywords 可多个；Outliner 可总览元数据。Revision Mode 用颜色区分修订，并可结合快照。[官方修订指南](https://scrivener.tenderapp.com/help/kb/general/revising-in-scrivener)
- **证据**：Binder 可以存放 outtakes、复制草稿文件夹、并排查看；文档也提醒组织好项目副本以免误判最新版。[官方修订指南](https://scrivener.tenderapp.com/help/kb/general/revising-in-scrivener)
- **判断**：采纳章节导航、版本回溯和阶段状态；不照搬多份正文副本作为默认会话机制。Composer 首版只有整篇快照，不宣称实现 Scrivener 的逐行比较。
- **证据缺口**：本页不确认 AI、账号或全部平台存储细节。

### novelWriter

**研究问题**：纯文本小说工具怎样降低格式操作成本，并在文档组织与叙事结构之间转换？

- **证据**：作品可拆成多个文档，自定义顺序、文件夹与子文档；元信息标签支持交叉引用。[功能页](https://novelwriter.io/features.html)
- **证据**：Novel View 用章和场景的标题而不是文件组织作品；Outline View 展示元信息与引用。[功能页](https://novelwriter.io/features.html)
- **证据**：并排 Document Viewer、隐藏项目树与查看面板的 Focus Mode，以及引用跳转和反向引用。[功能页](https://novelwriter.io/features.html)
- **证据**：Build Manuscript 可筛选小说、大纲或笔记，导出包括 Markdown、HTML 和办公文档格式。[功能页](https://novelwriter.io/features.html)
- **判断**：采纳专注模式、结构总览及导出边界；首版只提供章节级卡片，不承诺场景标签解析、拖动排序或出版级排版。
- **证据缺口**：本页不确认 revision、AI 或 session 的完整语义。

### Obsidian

**研究问题**：本地文件夹隔离与应用布局状态怎样分离？

- **证据**：Markdown 纯文本文件位于 vault 文件夹，允许其他编辑器和文件管理器修改；Obsidian 会刷新外部变化。[数据存储说明](https://obsidian.md/help/data-storage)
- **证据**：vault 配置在 `.obsidian`，布局在 workspace 文件，全局设置在平台应用目录；内部链接局限于 vault，官方建议不要嵌套 vault。[数据存储说明](https://obsidian.md/help/data-storage)
- **证据**：元数据缓存为派生索引，可重建。[数据存储说明](https://obsidian.md/help/data-storage)
- **判断**：采纳本地文件的可读性与配置分层；不复制 Obsidian 的命名，把 Composer 的 workspace 定义为作品根，而 session 定义为会话。首版尚无外部实时监听，只有保存时 hash 冲突检测。
- **证据缺口**：这些页面不能证明 Obsidian 的小说审阅能力或 AI 功能全貌。

### Novelcrafter

**研究问题**：AI 怎样拿到必要的故事设定，而不是把整部小说和所有资料塞进去？

- **证据**：Codex 聚合人物、地点、物件、资料和其他故事信息。[Codex 说明](https://www.novelcrafter.com/help/docs/codex/the-codex)
- **证据**：场景摘要的 + Codex 可添加指定条目到 scene beat completion 上下文；作者可在 prompt preview 中检查。[场景上下文教程](https://www.novelcrafter.com/courses/codex-cookbook/codex-scenes)
- **证据**：指南列出过多条目、重要细节埋在长文中、仅需一小段却发送整条、资料冲突与缺少场景规划等问题及解决方法。[场景上下文教程](https://www.novelcrafter.com/courses/codex-cookbook/codex-scenes)
- **判断**：采纳显式勾选资料、上下文范围说明与小说／设定联结；不承诺自动“理解全书”或 AI 必然服从每条设定。首版没有 token 精确计费预览。
- **证据缺口**：所读页未核实本地离线模式、账号和所有模型接口。

## 交互小说扩展

### Twine

- **证据**：story 由 passage 组成，有一个开始 passage；story format 处理玩家端呈现、条件、变量与媒体，编辑器本身不是播放器。[基本概念](https://twinery.org/reference/en/getting-started/basic-concepts.html)
- **证据**：作品可作为 HTML 在浏览器游玩，Twee 是不可单独游玩的纯文本形式；不同 story format 的做法差别大，切换可能耗时。[基本概念](https://twinery.org/reference/en/getting-started/basic-concepts.html)
- **判断**：未来选择式 IF 用场景图与独立运行时；导出应明确选定格式及语法子集，不声称“一键兼容所有 Twine 格式”。

### TADS

- **证据**：Adv3 有地点、角色、容器、光源、门锁、可携物件等世界类，以及感知、对话、命令解析和隐含动作机制。[对象库概览](https://www.tads.org/ov_lib.htm)
- **证据**：解析器处理对象歧义、复杂名词、代词和多命令，并允许新增语法。[对象库概览](https://www.tads.org/ov_lib.htm)
- **判断**：世界模拟必须有实体、位置与动作，不能仅是剧情跳转。中文 parser 需要单独研究；首期小说开发不引入此成本。

### Inform

- **证据**：Understand 映射输入命令到动作；动作定义对象需求；Check、Carry out、Report 分别约束、执行和报告，ACTIONS 与 RULES 可帮助调试。[新命令指南](https://ganelson.github.io/inform-website/book/RB_6_2.html)
- **判断**：后续规则视图应区分检查、效果与叙述，试玩提供规则日志；不在首版另造一门自然语言编程语言。

### Ren’Py

- **证据**：label、menu、jump、default、if 构成对白、分支与状态流程；scene／show／hide、转场和音频构成演出。[官方入门](https://www.renpy.org/doc/html/quickstart.html)
- **证据**：`.rpy` 是可编辑剧本，`.rpyc` 是编译产物；launcher 的 lint 不替代测试，发布前需要构建并测试分发包。[官方入门](https://www.renpy.org/doc/html/quickstart.html)
- **判断**：先验证选择式作品的有限映射，再导出 Ren’Py 源项目；世界模拟要明确阻断项和人工改编，而不是静默丢失行为。

## 决策矩阵

| 创作问题 | 借鉴方向 | Composer 首版 | 后续或未确认 |
|---|---|---|---|
| 找到章节与资料 | Scrivener、novelWriter | 左侧作品树、资料类型 | 场景层、拖动排序 |
| 专注正文 | novelWriter | 专注模式、独立正文排版 | 打字机滚动、组合输入优化 |
| 不覆盖旧稿 | Scrivener | 整篇快照、恢复、旧提案拒绝 | 逐行差异、修订批次 |
| 本地隔离 | Obsidian | workspace 根、session 状态 | 外部监听、迁移恢复 |
| AI 参考正确资料 | Novelcrafter | 当前章＋所选设定 | 分级 context、token 预算 |
| 选择式 IF | Twine | 不实现 | 场景图、状态、HTML runtime |
| 世界探索 | TADS、Inform | 不实现 | 实体、动作、规则、parser |
| 视觉演出 | Ren’Py | 不实现 | 演出层、子集导出 |

矩阵是本项目判断，上方各节是引用证据；没有将“未实现”归给竞品。应在实际作者试写和原生平台验收后再调整优先级。
