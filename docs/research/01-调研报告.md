# 小说先行的 Icimik Composer

本轮目标是验证一个适合专业程序员兼中文作者的独立桌面工作台，而不是罗列“AI 写小说”功能。产品约束已固定为 Electron、macOS／Windows、本地工作区隔离、可切换会话、必要 AI 与可复现 E2E；账号、登录、远程同步不在范围内。

## 研究方法与证据边界

- **来源**：优先官方文档与作者指定仓库；搜索用于找到来源，结论依据实际读取的文档。研究未进行竞品付费账户内的操作测试，不比较无法核实的价格、商业表现或所有未展示功能。
- **覆盖**：小说工作流比较 Scrivener、novelWriter、Obsidian、Novelcrafter；扩展模型比较 Twine、TADS、Inform、Ren’Py；工程依据 Electron 与 Playwright 官方文档。
- **区分事实与建议**：下文每条外部能力引用原页；“采纳／不采纳／排序”是 Composer 的设计判断，不宣称竞品缺少该能力。
- **未验证信息**：未在阅读页面中出现的账号、同步、完整导入能力等，记为“本页未确认”，不能据此作产品级否定结论。

## 关键结论

### 小说编辑器应以文稿和资料组织为中心

Scrivener 的文档级快照、比较和回滚，以及状态、标签、关键词，支持分阶段修订与回溯；其官方修订指南也提醒避免混淆多份项目副本。[Scrivener 修订指南](https://scrivener.tenderapp.com/help/kb/general/revising-in-scrivener)

novelWriter 提供项目树、按章／场景标题组织的 Novel View、带元数据与引用的 Outline View、并排查看与专注模式，且能构建并导出手稿。[novelWriter 功能](https://novelwriter.io/features.html)

**设计判断**：首屏必须先让作者看见章节、正文、资料和保存状态。复杂的 agent 调度、统计仪表盘和营销式欢迎页不应抢占主要写作空间。

### 本地作品与会话是两个不同概念

Obsidian 的 vault 是含 Markdown 的本地文件夹，可分离不同笔记集合；布局文件与 vault 内配置、全局配置分别存放，其元数据缓存可重建。[Obsidian 数据存储](https://obsidian.md/help/data-storage)

**设计判断**：workspace 是作品与配置的隔离边界；session 是该作品内的工作上下文，不创建新正文副本。切换工作区不能把另一部作品的模型设置、设定或提案带过来。

### AI 上下文应可见、可选、受限

Novelcrafter 的 Codex 存储人物、地点、物件和资料；作者可将指定 Codex 条目附加到场景 AI 上下文，并查看 prompt。官方指南也说明过多、过长或相互矛盾的条目会影响结果，应选择相关信息并明确优先关系。[Codex](https://www.novelcrafter.com/help/docs/codex/the-codex) [场景上下文](https://www.novelcrafter.com/courses/codex-cookbook/codex-scenes)

**设计判断**：首版 AI 只读取当前章节、当前指令、勾选设定和中文生成约束；生成产物是待采纳提案，不是自动改稿。文学质量不能仅由模型自评或机械评分宣称“通过”。

### 后续 IF 扩展需要保留正确的模型

Twine 将 passage 创作与 story format 执行分离；TADS Adv3 建模世界实体与命令解析；Inform 将动作条件、状态变化和结果叙述分离；Ren’Py 支持对白、选择、变量及图像音频演出。[Twine](https://twinery.org/reference/en/getting-started/basic-concepts.html) [TADS](https://www.tads.org/ov_lib.htm) [Inform](https://ganelson.github.io/inform-website/book/RB_6_2.html) [Ren’Py](https://www.renpy.org/doc/html/quickstart.html)

**设计判断**：当前资料 ID、文稿和模块边界为扩展留口，但不提前实现地图和运行时。未来也不把世界模拟强行编译成无状态选择图，不能承诺任意 IF 无损导出视觉小说。

### Electron 的可访问性不应变成权限开放

Electron 官方建议限制 Node 集成、启用 context isolation 与 sandbox、限制导航与新窗口、校验 IPC 发送方并避免向不可信内容暴露 Electron API。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

**设计判断**：正文和模型结果只作为文本渲染；渲染器不能任意读写磁盘或直接使用密钥。AI 请求在主进程执行，工作区访问由稳定 ID 和注册目录控制。

## 优先级依据

- **P0 数据不丢失**：文件保存、关闭刷新、冲突提示、可恢复历史。
- **P0 写作闭环**：作品、章节、设定、编辑、导出，不依赖 AI。
- **P0 AI 有用但可控**：生成／续写／表达优化、上下文边界、取消、采纳与拒绝旧提案。
- **P0 可复现验证**：临时工作区、mock API、真实 Electron UI 操作和原生平台 CI。
- **P1 框架深化**：模板、完整阶段门禁、多角色审阅、差异与联动资产。
- **后续选配**：IF、世界模拟、演出资源与 Ren’Py／Twee 导出。

## 尚待作者和原生平台验证

模型供应商与上下文预算、真实长章性能、中文输入法组合态、macOS Keychain、Windows DPAPI、文件权限失败、正式发行签名和真实作者连续写作体验仍需验证。当前自动化不能替代中文小说的人工审阅，也不能替代两个原生平台的发行验收。
